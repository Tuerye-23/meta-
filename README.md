# 映间 · Meta 旁聊

一个 SillyTavern / TauriTavern 前端扩展：从角色卡或世界书里整理人物，和不同角色分别聊天，也可以一起观看主线、留下批注、开小剧场，或开启一段陪伴。

## 这个窗口里的关系

角色沿用所选资料的人设、世界背景和与你的关系。原设定里是陌生人、朋友或恋人，就从那个基础开始。

主线中的双方，是另一个平行世界的版本。Meta 窗口中的双方可以一起阅读那边的故事，讨论各自的看法，也可以聊自己的日常。主线经历与 Meta 聊天记忆分别组织，Meta 回复和批注保存在扩展自己的存档中。

## v0.4.0 功能

- 新手机桌面：顶部实时时间、日期；小尺寸玻璃图标进入消息、共看、陪伴、联系人、朋友圈、日记、设置。底部横条返回首页；手机边框无侧面按键，PC 保留拖拽。
- 微信式朋友圈：用户可发文字 / 本地图片动态、点赞、评论；本地上传封面背景。点击自己的头像设置名字、微信状态、头像、可发动态及可评论的角色。
- 双日记本：角色日记 / 我的日记；用户写日记并评论角色日记，也可请获准的角色评论日记。可选生成角色、评论角色、点击手动生成、现实时间间隔及每个角色的每日上限。
- API 可选沿用酒馆当前配置或独立 OpenAI 兼容接口。独立配置支持地址、Key、模型列表读取 / 手动模型 ID、连接测试、温度、Top P / K、惩罚参数、随机种子和输出上限；可选参数留空不发送。
- 打开主线聊天时自动读取当前卡、内嵌世界书、角色卡绑定的主 / 附加世界书及聊天绑定世界书；群聊读取各成员卡。首次使用当前模型整理人物，后续复用缓存；素材发生变化时重新整理，保留已有聊天与手动修改的人设。
- 从多张角色卡、多本世界书和卡片内嵌世界书中提取人物。支持多人卡；提取结果可编辑，并保留素材原文。关闭的条目默认跳过，可选择包含。
- 每位角色拥有独立的 Meta 聊天和记忆。角色姓名、你的称呼、人设与关系、Meta 补充设定均可修改。
- 读取主线最近正文，以及柏宝书公开 API v1 提供的压缩历史和状态；未连接柏宝书时可直接读取最近正文。
- 自动跟随当前主线最新剧情：新增、编辑、删除、切换消息和切换聊天时刷新。发送 Meta 消息前也会读取最新内容。
- 按标签提取正文或排除状态栏等标签；同步当前已启用且获准使用的全局、角色卡、预设正则，选择正文正则的捕获组读取。不运行正则的 HTML 替换模板。
- 正文记忆来源二选一：柏宝书公开接口，或世界书指定条目的内容。世界书模式不读取柏宝书记忆。
- 请求角色为某段正文留下批注，单独保存。
- 开一段与主线独立的小剧场，之后可以继续聊。
- “一起挂着”：设置活动、主动搭话间隔和条数上限，记录陪伴时长；也可以手动请角色说一句。
- 查看本次上下文预览；手动或自动整理 Meta 记忆，可设置触发条数、近期原文保留条数及独立总结提示词；导入导出完整备份。
- 内置小手机界面：窄屏手机外框、首页 APP 图标和返回桌面横条，雾蓝液态玻璃配色；通过魔法棒菜单或 QR 打开。正文读取使用数据接口，兼容 TT 消息虚拟化。PC 可拖动顶部标题栏移动小手机；窄屏维持固定布局。后台同步保留阅读位置、展开状态和输入草稿。

## 安装

安装地址：**https://github.com/Tuerye-23/meta-**

1. 打开酒馆的 **扩展 → 安装扩展**。
2. 粘贴 `https://github.com/Tuerye-23/meta-`。
3. 安装完成后刷新，从聊天输入框旁的 **魔法棒 → 映间小手机** 打开；也可从扩展设置打开。
4. 更新时，在扩展管理里检查并更新此扩展，然后刷新。

TauriTavern 2.2.0 的 Git 安装接受匿名 HTTPS 仓库，所以使用公开仓库。直接从仓库加载，无需在用户设备运行 npm 或编译，也不需要 Node 后端插件。

开发者也可以把此仓库放到宿主的第三方扩展目录中进行本地测试。压缩包用于传递源码；TT 的“安装扩展”入口使用上面的 Git 仓库地址。

## 第一次使用

1. 选择可用 API：默认沿用酒馆当前模型；也可先打开映间的“设置 → API 配置”，选择独立 API。保存后，提取、聊天、批注、陪伴和总结均使用所选连接。
2. 打开酒馆主线聊天，映间会自动读取当前角色卡及绑定世界书，整理为联系人；无需先选素材。首次提取按约 12000 字符分段，每段调用一次当前模型，素材上限为 15 万字符。主线正在生成时等待这一轮结束。素材不变时，换同卡的聊天、重新打开或重启都复用已有资料。
3. 从魔法棒或 QR 打开映间，在“联系人”检查整理出的角色资料，保存修改，再切到“消息”。若想读其他卡或世界书，可以展开手动提取；也可以直接手动添加角色。自动提取失败时会提示，重新打开小手机可重试。
4. 想一起看正文时，打开对应主线即可自动同步。在“共看”里配置正文标签、正文正则和记忆来源，点击“保存读取设置”。
5. 想独立聊天时，在“设置”关闭“携带主线剧情”。想一起挂着时，在“陪伴”里设置活动并开始。

共看内容跟随当前打开的主线。切换主线后先清除旧的观看缓存，再读取当前内容；Meta 聊天和角色记忆不受影响。旧版固定进度在升级后解除。切换 Meta 角色时，返回中的回复仍保存到发起请求的那个角色会话。

扩展加载后会在快速回复扩展就绪时自动创建并启用“映间小手机”QR 集合，按钮执行 `/meta`。已有集合和按钮不重复导入，不覆盖其他 QR；首次导入及修复旧版失败导入时会启用快速回复显示，等待按钮内容保存，再激活集合；接口未就绪或暂时失败时重试。之后手动关闭 QR 或停用集合，重启不会强制重新启用。快速回复扩展关闭时仍可从魔法棒打开。

标签填写名称即可，例如 `正文` 或 `状态栏`，多项用逗号或换行分开。默认排除 think、thinking、analysis、script、style。筛选正文标签及正则只作用于角色回复，用户消息保留。正则读取默认捕获组 1（`$1`），可改为 0（完整匹配）或其他捕获组。标签与正则同时配置时，先按正则提取，再按标签筛选；替换模板不会执行。所选正则停用或不属于当前卡 / 预设时，会提示重新选择。

## 朋友圈与日记

从首页进入 **朋友圈**，点击“发朋友圈”写文字，也可本地选图（每条最多 9 张）。点击自己的头像打开状态和角色权限；“换背景”选择本地封面。图像在设备内缩放压缩后保存，不会发送到模型接口。支持 JPG / PNG / WebP，单张原文件不超过 12 MB。可点击动态照片查看大图。

**日记**有“角色日记”和“我的日记”两页。用户日记直接写入保存，可选标题；每篇记录下方有评论入口。用户可以评论角色日记；选择获准的角色，可调用生成接口评论用户或角色日记。朋友圈评论权限和日记评论权限分别设置。

**当前阶段：朋友圈生成、日记生成及其角色评论提示词按要求留空，集中保留在 `social.js` 的 `SOCIAL_PROMPTS`。没有提供自定义提示词界面；导入备份也不能修改这些提示词。发布、图片、状态、用户评论和日记保存可直接使用；角色生成入口暂时显示“待接入提示词”，不发起空提示词请求、不扣每日上限。作者提供提示词后再更新启用。**

两项功能均已接入统一 API、角色资料及 Meta 记录，生成结果保存到对应动态或日记，不写入主线正文。角色生成和评论都校验各自的许可名单，不受聊天页当前选择变化影响。

自动生成间隔使用现实世界分钟（1—10080），每日上限为每个角色、每种内容分别计算（1—100），按设备本地日期重置，手动和自动生成共用上限。设定首次开启或改变角色 / 间隔时，从保存设置的时刻起等待一个间隔；重启保留下一次时间。运行中的酒馆每 30 秒检查一次，前台且主线 / 映间没有在生成时运行，关闭小手机也可检查。浏览器 / TT 完全关闭时无法生成；回到前台处理到期任务，每次成功后重新等待完整间隔，不补发离线期间积压内容。失败后等待 5 分钟再试，不写入半篇日记或扣除成功配额。

## 模型与记忆

API 配置统一用于人物提取、聊天、批注、小剧场、主动消息、记忆总结，以及接入提示词后的朋友圈 / 日记 / 角色评论。

- **沿用酒馆当前配置**：使用宿主 `generateRaw()`，沿用当前 API、模型和采样参数。映间不再使用 `getContext().maxContext` 在发送前硬拦截；宿主及接口本身仍会处理各自的上下文限制。
- **独立 API**：使用 OpenAI 兼容 Chat Completions 协议，支持这类格式的官方接口或中转。原生 Anthropic Messages / Gemini 格式的地址不能直接填入，需要对应的 OpenAI 兼容地址。地址可填 API 根地址（例如 `https://example.com/v1`）或完整 `/chat/completions` 地址。填写 Key 和模型 ID，模型 ID 可手动输入或读取列表。

独立模式默认通过酒馆后端转发，兼容 TT 2.2.0 的原生网络层；可改为浏览器直连（接口需允许跨域）。独立请求使用单次请求的地址与凭据，不修改酒馆的主 API 设置或共享密钥。无鉴权的接口可以把 Key 留空。

温度、Top P、Top K、频率 / 存在 / 重复惩罚、随机种子和输出上限均可留空。留空时不发送对应参数，使用接口默认值；不会自动补入酒馆模式的回复上限或人物提取 / 总结的内部长度建议。填写 `0` 会发送数字 0。输出上限可选择 `max_tokens` 或 `max_completion_tokens`；不支持某参数的模型可以清空它。自定义请求参数支持 JSON 对象，例如 `{"reasoning_effort":"low"}`，用于接口特有设置。

独立 API 的上下文检查上限默认留空，不做本地检查。填了才使用宿主 tokenizer（不可用时以字符估算）做近似检查，它并非接口的精确 token 计数；可以清空此项交给服务端处理。请求超时默认 120 秒，可修改。连接测试和读取模型列表使用当前填写的配置；点击“保存 API 配置”后才用于正式聊天。连接测试会发起一次简短的模型请求。

API Key 保存在当前设备，聊天备份导出时清空 Key；换设备后重新填写。保存配置和重启不会将其他留空参数变成默认数值。

Meta 自行组织角色资料、关系、可选观看内容、Meta 记忆和最近聊天。长篇正文用预设无需整套复制到这里；可以在“Meta 回复要求”中填写自己的要求。

`{{user}}`、`{{char}}` 在角色资料中按对应人物替换。其他宏在发送时转成全角花括号文字，避免 `generateRaw()` 自动执行素材中的 `setvar` 等命令。当前版本没有实现动态预设变量或脚本驱动的人设解析。

较早聊天仍保留在完整存档中，但发送上下文有消息条数和剧情字符预算。可在“设置”开启自动总结，默认阈值 40 条、保留最近 12 条；自动总结默认关闭。每次 Meta 回复结束后检查尚未归入摘要的消息条数，达到阈值便将较早部分与旧摘要合并，近期原文继续发送。总结提示词留空时使用内置提示词，之后可随时替换。总结不读取主线和正文世界书记忆，也不会删除完整消息。失败时保留旧摘要及新回复，之后可以重试。记忆整理会额外调用模型。

发送预览显示映间交给宿主的内容，其他扩展仍可能通过酒馆生成事件修改最终请求。主线生成期间映间会等待用户重试，不主动中断主线。

## 陪伴的运行范围

主动搭话只在面板打开、当前选中陪伴角色、应用在前台且主线没有正在生成时触发。间隔可设为 2—120 分钟，每次最多 1—20 条。关闭面板、切换角色或进入后台会暂停；回来后重新等待一个间隔，不追发积压消息。重启应用后需要重新开始陪伴。主动生成失败会暂停这一轮自动搭话，可重新开始。

计时无需模型请求，提取人物、聊天、批注、小剧场、主动消息和记忆整理都使用当前模型额度。当前版本不负责手机后台推送、音频播放或语音通话；“一起听歌”等活动名称会作为双方聊天的背景。

## 存档

资料与 Meta 对话保存在当前设备的 IndexedDB（宿主提供 localforage 时沿用它，否则使用原生 IndexedDB），数据库不可用时使用 localStorage；旧版普通存储会自动迁入数据库。导出备份会包含角色、提取素材、观看记录、聊天、摘要、批注、朋友圈 / 日记与评论、本地图片、状态和定时设置。旧版备份自动补充空的朋友圈与日记，保留原聊天。换设备前请导出，在新设备导入；当前版本没有自动跨设备同步，API Key 不随备份导出。

导入替换映间现有存档前会提示确认。主线聊天仍由酒馆管理。
