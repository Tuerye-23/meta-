# 映间 · Meta 旁聊

一个 SillyTavern / TauriTavern 前端扩展：从角色卡或世界书里整理人物，和不同角色分别聊天，也可以一起观看主线、留下批注、开小剧场，或开启一段陪伴。

## 这个窗口里的关系

角色沿用所选资料的人设、世界背景和与你的关系。原设定里是陌生人、朋友或恋人，就从那个基础开始。

主线中的双方，是另一个平行世界的版本。Meta 窗口中的双方可以一起阅读那边的故事，讨论各自的看法，也可以聊自己的日常。主线经历与 Meta 聊天记忆分别组织，Meta 回复和批注保存在扩展自己的存档中。

## 安装

安装地址：**https://github.com/Tuerye-23/meta-**

1. 打开酒馆的 **扩展 → 安装扩展**。
2. 粘贴 `https://github.com/Tuerye-23/meta-`。
3. 安装完成后刷新，从聊天输入框旁的 **魔法棒 → 映间小手机** 打开；也可在扩展设置中展开「映间小手机」，点击「打开小手机」。
4. 更新时，在扩展管理里检查并更新此扩展，然后刷新。

TauriTavern 2.2.0 的 Git 安装接受匿名 HTTPS 仓库，所以使用公开仓库。直接从仓库加载，无需在用户设备运行 npm 或编译，也不需要 Node 后端插件。

开发者也可以把此仓库放到宿主的第三方扩展目录中进行本地测试。压缩包用于传递源码；TT 的“安装扩展”入口使用上面的 Git 仓库地址。

## API 来源与默认参数

独立 API 支持 OpenAI 兼容（`/chat/completions`、Bearer Key）和 Claude 原生（`/messages`、`x-api-key`）。地址可填到 `/v1` 或完整生成端点；模型列表不可用时可手动填写模型 ID。

默认参数：温度 1、Top P 0.98、频率惩罚 0、存在惩罚 0、输出上限 12000，超时 120 秒。点击“参数配置 → 恢复默认”后保存即可恢复这一组数值，连接地址、密钥、模型和流式选择保留。旧版标准 4096 预设自动升级，其他自定义配置保留。

留空时不发送对应参数。Claude 原生不发送频率和存在惩罚；温度与 Top P 同时填写时只发送温度，清空温度后才发送 Top P。Claude 的输出上限必填。OpenAI 推理模型的输出上限字段由模型 ID 自动选择，不再提供参数名选项。Top K、随机种子、重复惩罚和自定义 JSON 已移除。

设置中可开启或关闭流式输出。独立 API 支持 OpenAI / Claude SSE，聊天气泡实时更新；关闭时等待完整回复。沿用酒馆且启用流式时，使用宿主的聊天补全参数构造接口和原有模型、采样参数、输出上限，不改动主 API 设置。文本补全的宿主连接请关闭流式或使用独立 API。流中思考块不显示为消息正文，连接提前断开不会保存半截回复。

首页朋友圈为彩色光圈，设置为对称齿轮；顶栏返回与关闭按钮提供 44px 点击区域，关闭键为无边框图标。

## 第一次使用

1. 选择可用 API：默认沿用酒馆当前模型；也可先打开映间的“设置 → API 配置”，选择独立 API。保存后，提取、聊天、批注、陪伴和总结均使用所选连接。
2. 打开酒馆主线聊天，映间会直接读取当前角色卡，建立沿用模式的联系人；群聊每张成员卡对应一位联系人。读取设定无需连接模型，不占模型额度。主线正在生成时等待这一轮结束。
3. 从魔法棒或 QR 打开映间，在「联系人」查看人设。单人卡可保持「沿用角色卡人设」；要修改原始人设时切换到「独立人设」再保存。旧版提取的人设和已有聊天保留。
   多人共用条目时，点击“联系人 → 添加 → 世界书”，依次选择世界书和条目。确认条目后自动识别人物；勾选需要的人物，再点击添加，可批量建立。单个人沿用原条目，多人时只提取所选人设；提取兼容 Markdown 标题、姓名大小写与空白差异，人设中的常见小节标题保留为正文。漏提、重复、混入未选角色或人设为空时说明具体原因，整批不保存。姓名缩写和不同人物版本不会自动合并。识别与多人提取分别使用一次模型请求，单人沿用不额外提取。来源列表仅在选择页显示，人设仅在点入联系人之后查看。
   补充设定在“联系人详情 → 补充设定 → 补充世界书”选择，可继续点入每本世界书指定条目，保存后注入；未选择时不读取整本绑定世界书。
4. 想一起看正文时，打开对应主线即可自动同步。在“共看”里配置正文标签、正文正则和记忆来源，点击“保存读取设置”。
5. 想独立聊天时，在“设置 → 聊天记录设置”关闭“携带主线剧情”。想一起挂着时，在“陪伴”里设置活动并开始。

共看内容跟随当前打开的主线。切换主线后先清除旧的观看缓存，再读取当前内容；Meta 聊天和角色记忆不受影响。旧版固定进度在升级后解除。切换 Meta 角色时，返回中的回复仍保存到发起请求的那个角色会话。

扩展加载后会在快速回复扩展就绪时自动创建并启用“映间小手机”QR 集合，按钮执行 `/meta`。已有集合和按钮不重复导入，不覆盖其他 QR；首次导入及修复旧版失败导入时会启用快速回复显示，等待按钮内容保存，再激活集合；接口未就绪或暂时失败时重试。之后手动关闭 QR 或停用集合，重启不会强制重新启用。快速回复扩展关闭时仍可从魔法棒打开。

标签填写名称即可，例如 `正文` 或 `状态栏`，多项用逗号或换行分开。默认排除 think、thinking、analysis、script、style。筛选正文标签及正则只作用于角色回复，用户消息保留。正则读取默认捕获组 1（`$1`），可改为 0（完整匹配）或其他捕获组。标签与正则同时配置时，先按正则提取，再按标签筛选；替换模板不会执行。所选正则停用或不属于当前卡 / 预设时，会提示重新选择。

## 消息与头像

首页进入“消息”后显示最近聊过的联系人、最后一条消息与时间，可搜索或点击“新聊天”选择联系人。进入会话后，返回键回到消息列表。点击顶栏姓名或收到的消息头像进入联系人设置，其中可查看本次发送内容预览。

点击顶栏姓名，在联系人详情里展开「聊天设置」。聊天方式可选长段或短句，短句再选每次 3～5 条或 5～10 条，点击保存。只影响这位联系人，原人设与聊天草稿保留。短句按每个 `<消息>` 块拆成独立气泡；流式生成时分别更新气泡，完成后保存为同一组回复。重试替换这一整组，失败则保留原组；删除按钮仍只删除所在气泡。格式不完整或数量不符合当前范围时提示重试，不保存半截回复。

同一栏内可开启「主动发消息」，填写发送间隔（0.5～720 小时）与每日最多次数（1～100 次），点击「保存聊天设置」。开启或修改间隔后，从保存时起等待一个完整间隔；仅修改聊天方式或每日上限不改变到期时间。再次关闭后不再自动发送，手动聊天和陪伴页的「让他现在说一句」仍可使用。

输入栏左侧加号展开功能面板。表情会插入输入草稿；戳一戳记录一次互动并请求角色回应，保留正在输入的文字；一起挂着进入陪伴页。转账、照片、发语音目前仅预留入口。重试会重新生成最近一次角色回复；点击后立即隐藏旧回复，失败时恢复，重试戳一戳不会重复添加互动记录。

在消息列表点击“我的头像”，或点击聊天中的自己的头像，可修改用户头像；联系人详情中的头像及“角色头像”条目可修改该联系人的头像。选择本地图片或填写 HTTP / HTTPS 图片直链，预览后点击“保存头像”。本地原文件不超过 12 MB，头像在设备内缩放至最长边 320px 后保存。用户头像全局共用，联系人头像分别保存；更换头像不改变角色卡与人设来源。头像内容不会发送给模型。

## 朋友圈与日记

从首页进入 **朋友圈**，点击“发朋友圈”写文字，也可本地选图（每条最多 9 张）。点击自己的头像打开状态和角色权限；“换背景”选择本地封面。图像在设备内缩放压缩后保存，不会发送到模型接口。支持 JPG / PNG / WebP，单张原文件不超过 12 MB。可点击动态照片查看大图。

**日记**有“角色日记”和“我的日记”两页。用户日记直接写入保存，可选标题；每篇记录下方有评论入口。用户可以评论角色日记；选择获准的角色，可调用生成接口评论用户或角色日记。朋友圈评论权限和日记评论权限分别设置。

**当前阶段：朋友圈生成、日记生成及其角色评论提示词按要求留空，集中保留在 `social.js` 的 `SOCIAL_PROMPTS`。没有提供自定义提示词界面；导入备份也不能修改这些提示词。发布、图片、状态、用户评论和日记保存可直接使用；角色生成入口暂时显示“待接入提示词”，不发起空提示词请求、不扣每日上限。作者提供提示词后再更新启用。**

两项功能均已接入统一 API、角色资料及 Meta 记录，生成结果保存到对应动态或日记，不写入主线正文。角色生成和评论都校验各自的许可名单，不受聊天页当前选择变化影响。

自动生成间隔使用现实世界分钟（1—10080），每日上限为每个角色、每种内容分别计算（1—100），按设备本地日期重置，手动和自动生成共用上限。设定首次开启或改变角色 / 间隔时，从保存设置的时刻起等待一个间隔；重启保留下一次时间。运行中的酒馆每 30 秒检查一次，前台且主线 / 映间没有在生成时运行，关闭小手机也可检查。浏览器 / TT 完全关闭时无法生成；回到前台处理到期任务，每次成功后重新等待完整间隔，不补发离线期间积压内容。失败后等待 5 分钟再试，不写入半篇日记或扣除成功配额。

## 模型与记忆

API 配置统一用于人物识别、所选人设提取、聊天、批注、小剧场、主动消息、记忆总结，以及接入提示词后的朋友圈 / 日记 / 角色评论。

- **沿用酒馆当前配置**：关闭流式时使用宿主 `generateRaw()`；开启流式时使用宿主聊天补全参数构造接口。沿用当前 API、模型、采样参数及输出上限。映间不再使用 `getContext().maxContext` 在发送前硬拦截；宿主及接口本身仍会处理各自的上下文限制。
- **独立 API**：可选择 OpenAI 兼容 Chat Completions 或 Claude 原生 Messages。Gemini 原生格式请使用 OpenAI 兼容地址。地址可填 API 根地址（例如 `https://example.com/v1`）或完整 `/chat/completions` 地址。填写 Key 和模型 ID，模型 ID 可手动输入或读取列表。

独立模式默认通过酒馆后端转发，兼容 TT 2.2.0 的原生网络层；可改为浏览器直连（接口需允许跨域）。独立请求使用单次请求的地址与凭据，不修改酒馆的主 API 设置或共享密钥。无鉴权的接口可以把 Key 留空。

温度、Top P、频率 / 存在惩罚和输出上限可以留空（Claude 输出上限除外）。填写 `0` 会发送数字 0。剧情发送不再按字符截断；可用“最近正文条数”调整上下文范围。酒馆模式的回复上限由宿主配置决定。

独立 API 的上下文检查上限默认留空，不做本地检查。填了才使用宿主 tokenizer（不可用时以字符估算）做近似检查，它并非接口的精确 token 计数；可以清空此项交给服务端处理。请求超时默认 120 秒，可修改。连接测试和读取模型列表使用当前填写的配置；点击“保存 API 配置”后才用于正式聊天。连接测试会发起一次简短的模型请求。

API Key 保存在当前设备，聊天备份导出时清空 Key；换设备后重新填写。保存配置和重启不会将其他留空参数变成默认数值。

Meta 按定稿的顺序组织请求：头部（系统）、AI 提示词（模型）、任务说明、World Info (before)、Persona Description、Char Description、Char Personality、Scenario、World Info (after)、角色定义后的说明、Chat Examples、主线正文及剧情记忆、Meta 摘要和可读聊天记录、Post-History Instructions。世界书的前置 / 后置内容放入对应位置；其他位置的所选条目作为后置参考设定使用，不运行正文世界书的关键词、概率及深度激活引擎。可解析的对白示例保留用户 / 模型身份，示例属于参考资料。

「设置 → 提示词设置」仅提供头部和 AI 提示词两个编辑框，可以保存或恢复默认。其余聊天说明由扩展内置；旧版自定义 Meta 回复要求不再注入。OpenAI 兼容请求保留相对系统消息顺序；Claude 原生连接为了兼容不同版本模型，将系统内容合入顶层 `system`，用户 / 模型聊天身份仍保留。沿用酒馆模式时，宿主会按所选 API 协议进一步转换消息。

`{{user}}`、`{{char}}` 在角色资料中按对应人物替换。其他宏在发送时转成全角花括号文字，避免 `generateRaw()` 自动执行素材中的 `setvar` 等命令。当前版本没有实现动态预设变量或脚本驱动的人设解析。

较早聊天仍保留在完整存档中，发送上下文可按近期消息条数调整。可在“设置”开启自动总结，默认阈值 40 条、保留最近 12 条；自动总结默认关闭。每次 Meta 回复结束后检查尚未归入摘要的消息条数，达到阈值便将较早部分与旧摘要合并，近期原文继续发送。总结使用内置提示词，没有用户编辑界面；作者可以后续替换内置内容。总结不读取主线和正文世界书记忆，也不会删除完整消息。失败时保留旧摘要及新回复，之后可以重试。记忆整理会额外调用模型。

后台日志保留最近 200 条任务 / 错误记录，界面显示最近 50 条；可导出全部或清空。日志不主动记录聊天正文或请求密钥。

发送预览显示映间交给宿主的内容，其他扩展仍可能通过酒馆生成事件修改最终请求。主线生成期间映间会等待用户重试，不主动中断主线。

## 主动消息与陪伴的运行范围

主动消息由每位联系人的「聊天设置」控制，计时独立于陪伴会话和小手机窗口。酒馆运行且浏览器能执行任务时，会检查到期时间；酒馆或小手机正在生成时等待空闲。收起窗口、查看其他联系人或进入后台不重置到期时间。浏览器被系统暂停、页面关闭或应用退出后无法调用模型；恢复运行时检查已保存的时间，最多补发一次，再按间隔继续。每天按照本机日期统计成功的自动发送，失败、重试及手动搭话不额外消耗自动发送次数。

「一起挂着」单独记录陪伴时长，关闭面板或切换角色时暂停这段时长，重启后需重新开始陪伴；它不另外启动自动发送计时器。计时和直接沿用设定无需模型请求，所选人设提取、聊天、批注、小剧场、主动消息和记忆整理都使用当前模型额度。当前版本支持消息提示音，不负责手机系统推送、音乐播放或语音通话；“一起听歌”等活动名称会作为双方聊天的背景。

## 存档

资料与 Meta 对话保存在当前设备的 IndexedDB（宿主提供 localforage 时沿用它，否则使用原生 IndexedDB），数据库不可用时使用 localStorage；旧版普通存储会自动迁入数据库。导出备份会包含头部 / AI 提示词、设定来源绑定、运行日志、角色、提取素材、观看记录、聊天、摘要、批注、朋友圈 / 日记与评论、本地图片、状态和定时设置。旧版备份自动补充空的朋友圈与日记，保留原聊天。换设备前请导出，在新设备导入；当前版本没有自动跨设备同步，API Key 不随备份导出。

导入替换映间现有存档前会提示确认。主线聊天仍由酒馆管理。
